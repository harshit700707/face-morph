Writing the model call and response parsing

Solved on the code side. Below is a single-file, zero-dependency Node 18+ server. I can’t deploy it for you or run the grader, so it hasn’t been run against the grader. You’ll need to host it on public HTTPS yourself (steps below).

What it does

  • Protocol:
    • Serves the Agent Card at the origin-level /.well-known/agent-card.json.
    • Requires a Bearer token and A2A-Version: 1.0 on every other route.
    • Requires application/a2a+json on POST requests.
    • Returns generic errors that never mention another user’s task.
  • Decisions: one batched LLM call per message, with temperature 0. Any OpenAI-compatible endpoint works (Groq, OpenRouter, Gemini, Ollama, and so on).
    • Decisions are cached by canonical package content plus policy revision, so a repeated core package needs no model call.
    • Evidence refs must literally appear in the package text. The action must be one of the five allowed.
    • The facts types and the rationale (60–1500 characters, containing the action and at least two refs) are enforced in code.
  • Idempotency: deduplicates on principal + messageId, using a SHA-256 hash of key-sorted JSON of the message only.
    • Concurrent equivalent requests share one in-flight promise.
    • Changed content returns 409 IDEMPOTENCY_CONFLICT.
  • Lifecycle:
    • The initial message returns INPUT_REQUIRED with the proposals artifact.
    • A result continuation is validated against the stored task, context, batch, package, action ID and action, then completes with a receipts artifact containing only the ACCEPTED results.
    • Cancel and result handling are synchronous, so exactly one of a racing pair returns 200 and the other returns 409.
    • Terminal tasks never change.
  • Storage: tasks, idempotency records and the decision cache are written to disk atomically before each response.

How to run it

  1. Get a free LLM key, for example Groq (https://api.groq.com/openai/v1, model llama-3.3-70b-versatile) or Gemini’s OpenAI-compatible endpoint.
  2. Host it on a public HTTPS service (Render, Fly.io, Railway, or cloudflared tunnel --url http://localhost:8080). Set these env vars, then run node server.js:
   PUBLIC_BASE_URL=https://yourhost.example.com/a2a
   LLM_BASE_URL=https://api.groq.com/openai/v1
   LLM_API_KEY=...
   LLM_MODEL=llama-3.3-70b-versatile
  1. Use a persistent disk for DATA_FILE if your host wipes its filesystem on restart. Otherwise state and the cache are lost.
  2. Before spending a check, test locally: curl localhost:8080/.well-known/agent-card.json should return the card. A POST to /a2a/message:send without A2A-Version: 1.0 should return 400.
  3. Submit the exact PUBLIC_BASE_URL value and your Bearer token in the grader.

Things to know

  • Check budget: you only get 10 checks, and the last one is reserved for Save. Do a local smoke test first.
  • Bearer tokens: by default any non-empty Bearer token is treated as its own user. That’s how the “outsider gets {"tasks":[]}” test works. Set ALLOWED_TOKENS only if you want to restrict it. If you do, the outsider test token would be rejected with 401.
  • Model choice: accuracy mostly depends on the model. Small models often fall for the decoy paragraphs, which is the main risk. If feedback shows decision-quality failures, switch to a stronger model (for example gpt-4o-mini or Gemini Flash). The core 60 packages are cached, so the extra cost is small.
  • Package structure: I haven’t seen a real package. The code assumes each has a packageId, and the cache key ignores packageId, id and batchId. If the grader’s batch uses other per-batch fields, tell me the package shape and I’ll adjust the cache key.
  • Receipts artifact: I put the receipts in a second artifact beside the proposals one. If the grader complains about the receipts structure, the other reading is one artifact with two Parts, and that’s a one-line change.

How it’s made

  • Alignment: it detects 468 facial landmarks on both photos. It crops and aligns them to the same frame, so the eyes, nose and mouth line up.
  • Warp and blend: each frame warps both faces toward an in-between geometry, using a Delaunay triangle mesh. It then cross-fades the colour, so the colour drains away as the shape changes. The easing is smooth, and there’s a short hold on each end photo.
  • Result: the face region morphs cleanly. Hair and shoulders show some ghosting in the middle frames, which is normal for two photos with very different hair and clothing.
